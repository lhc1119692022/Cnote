# Cnote

Cnote 是一个本地优先的研究、创作与自动化工作台，由 **lhc1119692022** 独立开发和维护。

项目以可视化 Flow 为核心，把浏览、内容捕获、结构化整理、AI 处理、媒体生成和人工编辑连接在同一工作区中。桌面端是完整产品运行时，Web 版用于在线体验与兼容访问。

## 产品能力

- 可视化 Flow 编排与可恢复执行
- 内容、AI、浏览器、请求体、便签和分组节点
- 文本模型、图像模型和视频模型渠道配置
- 本地文件、网页、PDF、视频与社媒内容处理
- 模板、内容库、版本化备份和资源迁移
- 自定义本地数据位置与自定义媒体存储
- Windows 便携运行时与 macOS 便携构建
- GitHub Pages Web Preview

## Desktop 与 Web

两端共享 Flow 语义、数据结构、备份格式和主要界面，但不会为了表面一致而削弱桌面能力。

| 能力 | Desktop | Web Preview |
| --- | --- | --- |
| 浏览器 | Electron 原生会话与页面捕获 | 浏览器兼容嵌入 |
| 网络 | 主进程网络栈，可使用系统代理 | 浏览器网络栈，受 CORS 限制 |
| 密钥 | 主进程 SecretStore | 当前浏览器本地保存 |
| 数据位置 | 可选择本地存储目录 | 由浏览器管理，Cnote 上限为 10 GB |
| 内容解析 | 本地捕获与解析优先 | 可选的自有内容解析服务 |
| 长任务 | 本地任务队列、检查点与恢复 | 受页面生命周期限制 |

## 数据与远程服务

- Flow、内容、缓存、Cookie、任务和密钥默认保存在用户设备。
- GitHub 仓库和 GitHub Pages 不保存用户数据。
- 内容解析、API 代理和媒体存储均为可选的自有服务。
- 仓库不内置、不公开也不绑定任何维护者或个人部署实例、存储桶、服务地址或访问令牌。
- R2 存储桶、Worker 与 Cnote 项目彼此独立；Cnote 只保存用户主动填写的服务地址和令牌。

## 仓库结构

```text
Cnote/
├── web/       # React Web Preview 与共享产品界面
├── desktop/   # Electron 桌面运行时和本地能力
├── workers/   # 可选远程服务的通用源码与契约测试
├── docs/      # 产品、架构、同步规则与设计规范
└── .github/   # 自动检查、Pages 和便携包工作流
```

## 架构约束

- Desktop 是完整产品语义的权威运行时。
- Web 端对共享能力提供兼容实现或明确降级。
- 平台差异通过 Runtime Port 和 Adapter 隔离。
- 高权限能力只通过受控 IPC、最小授权和可审计边界提供。
- 用户配置、个人服务和构建产物不进入源码版本线。

项目内部规则位于 [`docs/desktop`](./docs/desktop/) 与 [`docs/design-system.md`](./docs/design-system.md)。
