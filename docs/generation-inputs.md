# 生成节点的素材、模式与参数

## 素材来自哪里

节点预览、单节点生成和 Flow 执行共用 `withGenerationUpstreamInputs`。连线、断线、上游禁用及素材更新会立即反映在素材栏中；图片、视频和音频按资源 ID 或地址去重。Flow 中刚完成的生成任务也通过同一解析器读取结果。

上游素材显示引用标记，不复制到节点自有素材列表。移除引用不会删除源文件；可用恢复图标重新启用。排序、首尾帧角色和排除状态以覆盖配置保存，执行时应用；断线后不会残留一份过期素材。图片节点根据实际合并后的素材自动选择文生图或图生图。

## 视频模式不是能力清单

菜单最多两个入口：多模态和首尾帧。文生与图生只是多模态入口下参考素材的不同组合，不是独立工作流。只展示当前模型适配配置支持的入口：

| 工作流 | 素材栏 | 视频 API 请求字段 |
| --- | --- | --- |
| 多模态 | 素材可为空；可添加模型允许的图片、视频、音频 | 无素材时不含素材字段；有素材时用 `reference_images`、`reference_videos`、`reference_audios` |
| 首尾帧 | 一张首帧、一张尾帧 | `input_reference`、`image_end` |

808Relay 的 Seedance 请求先隔离界面模式，再按提供商已确认的接口选择字段。补充的六模型文档对应 `seedance-2-pro/fast/mini`、`seedance-2.5-pro`：推荐省略 `mode`，由 `reference_images/reference_videos/reference_audios` 或首尾帧字段自动判断。`sd2-5-720p` 专用文档对应 `image_urls/video_urls/audio_urls`，参考请求使用 `mode: reference-to-video`。其他尚未确认接口归属的 Seedance 别名保留现有显式模式兼容路径，不因系列相同就认定属于同一接口。

显式模式兼容路径中，无素材为 `text-to-video`，参考素材为 `reference-to-video`，单首帧为 `image-to-video`，双帧为 `start-end-to-video`。单张多模态图片始终作为参考，提示词不改变素材角色。首尾帧仍须用户主动选择，不能由自动判断混入参考请求。无需增加第三个“自动”UI 入口；接口自动判断已包含在渠道适配中。以上模拟验证没有执行真实付费生成。

新节点默认多模态；添加或移除参考不会切换入口。多模态中的单张图片也是参考图片，不再因为只有一张就改成首帧字段。切换到首尾帧才显示两个帧槽并检查帧角色；切回多模态时图片保留，提交为普通参考。模型不支持的素材不会静默丢弃，而是显示校验提示。

Kacang H3 的声音由提示词描述，当前公开协议没有独立的音频布尔开关。参数菜单统一显示“生成音频”复选框，H3 始终勾选且禁用，说明放在悬停提示中；不发送未经确认的 `generate_audio`。支持独立开关的其他模型继续允许勾选或取消。所有时长统一使用数值输入框：连续范围按一秒增减，离散档位按相邻合法值增减，固定时长禁用增减。手工输入在失焦或回车时归入最近的合法档位，保留上下界约束。

## 视频提示词中的 `@` 素材引用

视频节点载入素材后，在提示词中输入 `@` 会打开当前节点素材菜单。菜单展示缩略图、名称、类型和稳定 token，可用鼠标点击，也可用上下键选择并按 Enter 或 Tab 插入。引用以 `referenceId -> token` 映射保存，因此素材重排不会改变已插入 token 的含义；删除本地或上游素材时，提示词中的引用会变为 `[已移除图片]`、`[已移除视频]` 或 `[已移除音频]`，需要用户修复后再提交。提交时 token 保留在 prompt 中，同时素材仍按现有协议适配为 `reference_images`、`reference_videos` 和 `reference_audios`。

旧配置中的文生、图生、视频参考、音频参考和视频编辑归入多模态；旧首尾帧保持不变。旧“生成音频”模式及未保存模式的历史配置仅在已有尾帧角色时恢复首尾帧，否则归入多模态。历史单张图生视频在新提交时不再使用 `input_reference`；已经提交的任务仍使用原始快照恢复轮询，不重新提交或修改远端任务。

模型目录是客户端适配配置，不是渠道返回的能力证明。“多模态”是统一的界面入口，不代表所有模型都支持所有素材：类型和数量仍按模型配置限制，纯文本也需要对应能力。未知视频模型使用宽松推断配置，但开放入口不等于渠道已经支持相关请求字段；有官方素材档案也不能代替渠道的请求协议。此改动不扩展或重新认证现有目录中的模型数量、时长、分辨率等限制。

模型名称先通过共享特征识别器得到系列和版本，再进入该系列下的渠道分支。供应商前后缀、命名空间、大小写和常见分隔符不会要求重新枚举完整型号。相同的 Seedance 别名在 808Relay 和 Kacang 下绑定不同的时长/请求协议；Kacang 并非跳过适配，而是根据自己的素材字段表达参考及首尾帧语义。模型列表、素材档案和实际提交共用这一解析，原始请求模型 ID 保持不变。

## 音频参数

支持音频输出的模型只显示一个“生成音频”开关，对应 `generate_audio`。参考音频是输入，与是否输出音轨分开。旧 `noMusic=true` 曾在客户端强制关闭音频，读取时按关闭音频处理；切换唯一开关时清除旧值。历史合同中的 `sound_effects` 会映射为 `generate_audio`。新请求不再额外发送 `no_music` 或 `sound_effects`，也不会向未配置音频输出能力的模型发送该参数。

## 校验与验证边界

所有视频渠道统一清理素材角色：视频只能作为参考视频，音频只能作为参考音频或参考声音，历史非图片尾帧角色不能把节点恢复成首尾帧模式。请求中的首尾帧字段只允许来自图片。素材上传前检查选定渠道是否配置了对应的参考或首尾帧字段；缺失时明确报错，不上传、不丢弃素材，也不借用另一渠道的字段。Kacang 的部分 S/H3 目录条目只有参考素材字段，不能仅因为官方模型档案开放了首尾帧就推断该渠道的帧参数。

跨渠道回归覆盖两套预设的 28 个模型、121 组成功参考请求及其他被明确限制的组合，以及 26 条首尾帧映射或拦截路径。另有 Kacang 的 Grok 单图参考/首帧、Doubao 成对帧、S 线路条件限制和旧配置回归。该检查验证客户端的请求规则，不证明远端当前线路全部可用；不能将 808Relay 的 `mode` 值普遍添加到 Kacang、Wan 或未知模型上。线上文档来源与未确认项见 `video-provider-contract-audit.md`。

模式、素材类型、数量、首尾帧、时长、分辨率、比例及音频能力在上传素材之前校验。失败时不上传、不创建任务，也不自动改用另一种素材传输方式。恢复轮询仍使用提交时的快照，不重新拼接当前连线。

`npm run test:generation-inputs` 覆盖真实组件的连线预览、模式联动、引用移除与恢复、角色覆盖、音频开关，以及生产请求构造与各传输分支。网络请求在测试中全部替换为 mock，不代表特定供应商已通过端到端验证。
