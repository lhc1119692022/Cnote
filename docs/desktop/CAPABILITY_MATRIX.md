# Desktop 能力矩阵

## 使用方式

本矩阵区分四种能力状态：

- **Desktop Full**：桌面端的完整本地实现。
- **Desktop Fallback**：桌面端在本地能力不可用时使用的远程或兼容实现。
- **Web Preview**：线上版可以稳定提供的能力。
- **External Boundary**：即使桌面化也不能保证突破的外部限制。

## 总体矩阵

| 领域 | Desktop Full | Desktop Fallback | Web Preview | External Boundary |
| --- | --- | --- | --- | --- |
| 网络请求 | 主进程直连、代理、WebSocket、本地服务 | 用户自己的 AI/内容 Worker | 浏览器 fetch + Worker | 上游权限、配额、地区和服务状态 |
| API 密钥 | 操作系统安全存储，主进程使用 | 用户配置的远程代理 | 本地浏览器存储或代理 | 密钥本身的有效性和服务商策略 |
| 浏览器 | 原生浏览器会话、标签、Cookie、下载、DOM | 远程解析或外部浏览器 | iframe、外部打开和链接传递 | 登录权限、验证码、DRM、网站自身策略 |
| 页面捕获 | DOM、截图、正文、媒体、附件、网络元数据 | Content Worker | URL 和远程解析结果 | 页面不允许访问或内容需要授权 |
| URL 解析 | 本地 HTML 解析器、渲染后解析、站点适配器 | Cloudflare Content Worker | 公开 URL 解析 | 上游反爬和不可读内容 |
| 文件处理 | 文件系统、目录监听、大文件、批处理 | 远程转换服务 | 文件选择、IndexedDB、浏览器下载 | 操作系统权限和文件格式本身 |
| 媒体处理 | FFmpeg、OCR、ASR、抽帧、压缩 | 远程媒体服务 | 有限的浏览器播放和解析 | 编解码器、版权和硬件能力 |
| Flow 执行 | Desktop Job 持久化、节点检查点、取消、重启后继续入口；Native Runner 已承接本地解析/网络任务，完整 AI/浏览器编排仍在 renderer | 远程任务或前台兼容执行 | 页面内执行 | 上游网络和本地资源状态 |
| AI 模型 | 远程 API、本地模型、自定义协议 | 用户自己的 Worker | 浏览器直连或 Worker | 模型权限、配额、内容策略 |
| 搜索与索引 | 本地全文索引、向量索引、内容关联 | 远程搜索服务 | Flow 内搜索和简单筛选 | 索引质量和资源规模 |
| 任务触发 | 定时、文件变化、浏览器事件、手动触发 | 远程调度 | 页面打开期间的手动触发 | 系统休眠和用户权限 |
| 系统集成 | 快捷键、剪贴板、通知、外部应用、协议处理 | 浏览器下载和分享 | 浏览器 API 能力 | 操作系统权限和安全策略 |
| 插件扩展 | 本地插件、脚本、解析器、节点和工具 | 远程扩展服务 | 预置节点和配置 | 插件自身权限与第三方协议 |
| 数据存储 | 文件系统 + 数据库 + 安全存储 | 远程备份 | IndexedDB + `.cnote.zip` | 磁盘损坏和用户删除 |
| 诊断与恢复 | 任务日志、崩溃恢复、诊断包、版本迁移 | 远程日志 | 浏览器控制台和错误提示 | 操作系统崩溃和第三方服务日志 |
| 发布更新 | 安装包、签名、增量更新、回滚 | 手动下载旧版本 | GitHub Pages 自动发布 | 平台签名和系统安装策略 |

## Desktop 第一阶段必须具备

第一阶段不需要一次完成全部矩阵，但以下能力不能继续依赖 Web 方案：

1. 主进程网络层和受控 IPC。
2. 原生浏览器会话。
3. 页面快照和本地内容解析。
4. 本地文件系统资源管理。
5. 可持久化、可取消、带检查点并能明确恢复的任务。
6. 操作系统安全存储。
7. Web 与 Desktop 的版本化备份格式。

## Desktop 第二阶段差异化能力

- 浏览器会话配置文件和登录态复用。
- 页面元素选择与结构化提取。
- 目录监听和批量内容导入。
- OCR、ASR、FFmpeg 等本地处理。
- 本地全文索引和内容关联。
- 本地模型或局域网模型接入。
- 定时任务和事件触发。
- 插件、脚本和自定义节点。

## 暂不作为第一阶段承诺

以下能力可以规划，但不应在第一阶段阻塞桌面核心：

- 多人实时协作；
- 跨设备自动云同步；
- 社区插件市场；
- 全平台同时发布；
- 复杂团队权限系统；
- 自动突破第三方网站的安全策略。

## 关键验收标准

桌面端的能力验收不以“Web 页面能否显示”为标准，而以以下结果为标准：

- 页面可以在原生浏览器会话中被用户正常访问。
- 已授权页面可以生成可追溯的页面快照。
- 内容解析不依赖 CORS 或公共服务才能完成。
- 长任务在窗口关闭或应用重启后有明确的恢复结果。
- API Key 不暴露给远程网页。
- Web 版无法提供的能力在 Desktop 中不需要通过浏览器妥协。
