# Desktop 会话与迁移默认规则

这份文档把目前不需要用户掌握技术细节的选择，先固化为可回滚的产品默认值。它们不是永久锁死的协议；如果真实使用中发现不合适，应通过版本化配置和迁移调整，而不是让用户承担技术决策。

## 1. 浏览器会话默认值

### 默认行为

- 每个工作区有一个默认浏览器会话配置。
- 会话配置默认持久化，因此用户可以正常登录并在下次打开 Cnote 时继续使用登录态。
- 新建的“隔离会话”使用独立 Cookie、LocalStorage、缓存和权限，不与默认会话共享。
- 会话可以被多个 Flow 节点引用；节点引用会话，不拥有会话本身。
- Cnote 不读取用户系统浏览器的 Cookie，也不默认复用 Chrome/Edge 的个人资料。
- 网页请求摄像头、麦克风、通知等操作系统权限时默认不自动放行；后续由会话设置提供逐项授权。
- 用户可以在会话设置中显式选择“新建隔离会话”“复制当前会话配置”或“清除会话数据”。

### 第一阶段支持

- 登录态和 Cookie 持久化；
- 基本标签页/窗口导航；
- 刷新、后退、前进和打开新窗口；
- 页面正文、DOM 快照、标题、最终 URL 和截图捕获；
- 下载目录和下载记录的受控管理；
- 页面捕获时保留来源、时间和会话 ID。

### 后续增强

- 页面元素选择和结构化提取；
- 可授权的页面脚本和自动化步骤；
- 会话级代理、UA、权限和下载策略；
- 工作区级会话备份（默认不导出 Cookie）。

### 明确边界

桌面端不会承诺绕过验证码、反爬、DRM、服务商权限、配额、地区限制或操作系统安全策略。“解除限制”指不再受到 Cnote 自己的 iframe、CORS、渲染层密钥和页面生命周期限制，而不是突破第三方的授权边界。

## 2. Web 与 Desktop 数据迁移默认值

### 第一阶段：文件迁移，不做云同步

- 继续使用现有 `.cnote.zip` 作为 Web/Desktop 的交换入口。
- Desktop 导入时走迁移向导：校验 manifest、迁移 schema、复制本地资源，并报告降级项。
- Desktop 导出时只导出 Web 能理解的子集；桌面专属对象（会话、任务、插件、系统路径等）不会被伪装成 Web 数据。
- API Key、Cookie、系统路径和本地机密永不进入普通备份文件。
- GitHub 只同步代码，不同步用户 Flow、资源、Cookie、任务和密钥。

### 迁移文件的长期演进

每个备份都应包含：

- `format`：交换格式名称；
- `version`：格式版本；
- `schemaVersion`：领域对象版本；
- `capabilities`：导出端支持的能力；
- `resources`：按内容哈希组织的资源索引；
- `warnings`：导入时可能需要用户确认的降级信息。

旧版本通过显式迁移函数升级，不能依赖“当前代码碰巧还能读”。

### 暂不实现

- 账号体系；
- 多设备实时同步；
- 自动上传用户资源到云端；
- 自动迁移系统浏览器 Cookie。

这些能力以后可以单独设计，但不应阻塞 Desktop 核心能力落地。

## 3. 需要真实使用后再决定的事项

以下不是启动桌面端的前置问题，而是第一轮垂直切片后根据体验决定：

1. 默认会话是否需要按项目进一步隔离；
2. 浏览器捕获是以“当前页面快照”为主，还是增加持续监听；
3. 是否允许任务自动打开登录页面并等待人工确认；
4. 是否引入可选的加密迁移包（包含用户主动选择的秘密）。
