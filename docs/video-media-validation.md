# 视频素材官方规格与本地图片适配

## 规则来源与优先级

素材规格使用 `official-media-rules.ts` 中独立于渠道的模型档案。初始来源为用户提供的三张官方规范截图，规则版本为 `2026-09-19.1`。模型 ID 的已知别名映射到 Wan 3、Seedance 2.0、Seedance 2.5 或 MiniMax H3；不能因为切换中转渠道改变同一模型的素材限制。

官方档案覆盖旧渠道目录中的输入类型与素材数量限制，不取渠道和官方限制的最小值。截图没有给出的数量不凭渠道补写。生成输出时长、分辨率和接口字段合同仍沿用原有实现；它们不是本次输入素材规格。未映射模型维持宽松处理，显示“未配置官方规格”，不声称通过官方校验，也不进行图片适配。

单文件大小采用十进制，1 MB = 1,000,000字节。Seedance 图片要求严格小于30 MB，其余按对应的“不超过”边界处理。请求体64 MB限制与单文件大小分开检查。透明通道不参与校验。

| 模型 | 图片 | 视频 | 音频 |
| --- | --- | --- | --- |
| Wan | ≤20 MB；每边240–8000px；长短边比≤8；JPEG/PNG/BMP/WebP | ≤100 MB；每边240–4096px；长短边比≤8；1–15秒；≥16fps；MP4/MOV | ≤15 MB；1–15秒；WAV/MP3 |
| Seedance | <30 MB；每边300–6000px；宽高比0.4–2.5；JPEG/PNG/WebP/BMP/TIFF/GIF/HEIC/HEIF | ≤200 MB；每边300–6000px；宽高比0.4–2.5；407696–8295044像素；24–60fps；MP4/MOV；H.264/H.265 | ≤15 MB；WAV/MP3 |
| H3 | ≤30 MB；每边256–5760px；JPEG/PNG/WebP/HEIC/HEIF；常规参考≤9张；首尾帧另检查0.4–2.5宽高比 | ≤50 MB；每边256–5760px；宽高比0.4–2.5；2–15秒；H.264/H.265 | ≤15 MB；2–15秒；WAV/MP3 |

- Wan 视频、音频分别累计≤15秒。
- Seedance 2.0视频、音频分别≤3个，单段2–15秒，各自累计≤15秒。
- Seedance 2.5视频、音频分别≤10个，单段2–30秒，各自累计≤30秒；视频编辑输入至少4秒。
- Seedance视频内音频接受AAC/MP3，MOV额外接受PCM；H3视频内音频接受AAC/MP3。
- H3视频、音频分别≤3个，各自累计≤15秒，混合输入总数≤12，提示词≤7000字符。
- 常规参考图片、首尾帧图片、视频、音频各自独立检查，不将H3图片条目扩展为多模态总规则。

## 添加、连线与切换模型

内容节点新增独立“音频”类型，支持本地音频导入与直接音频链接。播放器提供真实波形、当前时间/总时长、播放暂停和进度定位，并使用深浅主题颜色。通用导入入口接受MP3、WAV、M4A/AAC、FLAC、OGG/Opus、AIFF等；实际播放取决于运行环境解码能力，无法播放会提示。为控制波形开销，超过30MB不解码波形，保留播放与参考功能；波形不可用时显示基线，不伪造波形。

音频节点连至视频生成节点后派生为audio参考，并继续执行模型音频格式、体积、时长及数量限制。能够导入不意味着目标模型接受，不进行音频转码或自动更换模型。

普通画布导入不受某个视频模型限制。视频节点的上传和连线使用同一校验入口；检查失败不建立有效连接，并保留文件名、实际值和要求的原因说明。视频、音频只检查、不修复。实际文件头、媒体容器和轨道信息优先于扩展名及声明的MIME。

切换模型、输入模式，上游内容替换及恢复画布时重新校验，不自动生成副本。合规连线保留；不兼容连线断开。集合超限按既有输入顺序处理，尽量保留前面可合法加入的输入。一个上游节点输出多份素材时，只要其中有不合规输入，就断开该上游的整条边。节点内本地素材移出有效输入，但保留原始资源。

只有用户重新添加或重新连线才会执行适配。取消、删除节点、切换模型或改变输入后，过期检查结果不能建立连接。同一节点的添加操作串行确认，避免快速连线绕过数量限制。

提交生成前再次检查实际输入文件和集合规则，校验失败不创建供应商任务。规格检查成功不代表地址长期有效或渠道一定接受；地址可读性和供应商错误分别报告，不自动换模型、换渠道或重试生成。

## 图片无感适配

视频节点胶囊中的图标开关默认关闭，开启时呈绿色；只有开启后，新接入的不合规图片才进入固定适配流程。

1. 文件大小超限，先以固定最高编码质量100转换WebP。
2. 检查像素尺寸；超过上限时等比例缩小至上限，从原始解码结果生成最终WebP，质量仍为100。
3. 最终文件完整复检；仍超限直接报告失败，不降质、不为缩减体积进一步缩小。

不处理比例错误、低于最小尺寸、裁剪、补边、去透明，也不处理视频和音频。最高质量100不等于无损保证。格式本身不支持且没有体积或尺寸超限时，只报告格式错误，不引入额外的转换分支。

原图和副本分开存储。图片适配成功后，在上游图片节点附近创建独立可见的“适配副本”图片节点，显示处理后的真实文件；由副本节点连接视频节点，不建立原图到视频节点的替代连线。原图节点及其其他连接保持不变，预览、连线与提交使用同一份副本文件。节点内直接上传图片触发适配时，同样创建可见副本并连线。失败或取消不留下副本节点或有效连线。

副本节点与连线在同一步提交，支持撤销、重做和保存恢复；原有参考角色、顺序及提示词引用转移到副本。旧文档中的隐藏副本关联在恢复时转为可见节点，不重新编码。处理缓存以原文件内容校验值和处理参数识别，不仅按URL或文件名判断。断线不删除独立副本节点，资源沿用现有引用审计、撤销保护和七天未引用回收机制。

处理在可取消的Worker中执行，全局同时最多一个检查/处理任务，单次超时120秒。适配超过8000万像素时停止，不无限尝试。媒体容器使用Mediabunny只读解析，不引入FFmpeg；生产构建将所需解析代码放在独立Worker中。

文档版本升级为3，旧文档迁移后开关默认关闭，新增状态和副本关联随节点保存。无法解析的HEIC/TIFF等文件会明确报告无法检查，不以文件名猜测通过。
