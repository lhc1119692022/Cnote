# Cnote 画布体验优化计划

> 2026-09-19 用户范围调整：移除来源定位功能，不迁入菜单或标签交互。AI上游标签、生成文本预览和素材引用均不再提供定位按钮；专属组件和事件监听已清理。保留变量插入、拖拽、上游预览、来源文字提示及原有适应视图/节点列表导航。下文历史完成描述中的“来源定位”不再属于交付或验收范围。

## 一、目标与执行依据

**目标：完成现有画布的性能、节点输入和导航体验优化，完成自动验收，最后提供逐项实机测试表，由用户自行测试。**

沿用原计划，不另建路线。四部分的职责明确如下：

- **第一部分：**明确目标、依据和边界。
- **第二部分：**安排实施阶段与推进顺序。
- **第三部分：**把此前的分析结论转成必须落实的具体改动，合并到第二部分执行。
- **第四部分：**规定验证、交付和完成标准。

**第二、三部分共同构成实施范围。第三部分不是结论存档，也不是可以跳过的附录；同一项改动只实施一次，但必须同时满足对应阶段与专项要求。**

### 执行边界

- 保留自研画布、内容抬升架构、现有传输与安全边界、文档格式和视觉风格。
- React Flow 的历史替换针对领域重构和内容抬升，不能据此声称它性能必然更差。本轮优化当前引擎，不改回 React Flow。:codex-annotation{index="1"}
- 保留工作区已有生成、渠道、媒体相关改动，不回滚、不覆盖。
- 自动验证使用本地模拟服务，不调用收费 AI 或生成服务。
- 自动验证只运行不打开窗口的功能脚本、类型/静态检查与构建。凡需要打开产品或仿真窗口的交互、视觉、流畅度、浏览器资源检查，均由用户操作；不以脚本夹具结果替代实机结论。
- 既有分析用于指导实施；后续检查发现具体实现问题，应修复实现，不重新扩展为无关的方案选型。

### 当前状态

第二、三部分的代码改动已落实，最新代码的 16 组无窗口功能回归、类型检查、静态检查、Web/桌面前端构建及桌面主进程构建已通过。保存入口已统一读取最新视口，生成节点上游文本预览与来源定位已补齐。

按用户最新要求，窗口式自动验证已经停止。已有窗口夹具记录（包括中断、超时和已完成片段）只归档为诊断材料，不作为产品性能或实机验收通过的依据，也不再作为开发交付的前置任务。实际交互、显示、流畅度与资源表现由用户按 33 项表格检查，当前均为“待测”。

## 二、分阶段实施

| 阶段 | 实施内容 | 当前收尾重点 | 完成标准 |
|---|---|---|---|
| **P0：产品基线** | 固定 30、100、300 节点逻辑场景，留存改动前源码；准备对应实机检查步骤 | 无窗口逻辑记录与实际界面记录分开；后者由用户执行 | 源码及脚本来源可追溯；不把模拟场景或窗口夹具当作真实产品体验结论 |
| **P1：手势合帧与批量更新** | 平移、缩放、拖动、框选、调整大小、连线预览按帧处理；增量累加，绝对位置取最新值；多节点一次提交 | 最终位置、取消、复制拖动、失焦、隐藏、卸载和文档切换 | 不丢位移或最后一帧；一次手势一次撤销；取消不遗留副本和待执行更新 |
| **P1：AI 显示合批** | 网络及时读取，显示按帧合并；后台定时兜底；缩小会话订阅范围 | 完成、停止、异常和退出时处理剩余文本；节点与侧栏保持一致 | 不丢尾字、不重复、不串会话；无关节点不随输出反复刷新 |
| **P1：会话增量保存** | 未变化的 AI 会话避免重复编码；成功保存后才更新缓存状态 | 失败重试、删除重建、保存期间新更新；记录图文档编码和历史深拷贝成本 | 保存恢复一致，不丢更新、不复活删除数据；不扩大为存储格式重构 |
| **P2：视口与渲染隔离** | 分离实时视口与持久化视口，缩小状态传播，缓存连线路径 | 保存、菜单、命中和导航读取同一最新视口；补齐立即保存和导航打断边界 | 静态正文不因纯平移重渲染；节点、连线、菜单与点击位置一致 |
| **P2：局部缩放与生命周期** | 落实第三部分的局部 transform、按节点保活和屏幕距离预加载策略 | 脚本检查类型例外及保活规则；真实编辑态、离屏状态和浏览器资源由用户检查 | 代码与逻辑回归完成；实际排版、命中及状态体验单列为用户待测 |
| **P2：上游输入与来源追踪** | AI 与生成节点共用直接上游规则，过滤禁用/删除节点、去重并保留顺序 | 补齐生成节点的上游文本预览与来源定位；发送时重新读取最新快照 | 预览与同一快照的提交一致；正文、URL、空输出可区分；旧引用、渠道及结果关联兼容 |
| **P3：背景与导航** | 落实世界坐标网点和约 220ms 的可中断导航 | 连续改目标、手动打断、减少动态效果、负坐标和主题表现 | 最后目标生效；用户操作立即接管；旧动画不会拉回视口 |

### 内部接口约定

- **节点更新：**同一帧的多节点变化走统一批量入口，保持原撤销语义。
- **视口：**读取、订阅、设置、结束提交及取消使用同一状态来源，保存不得读取落后的视口。
- **上游输入：**共享结果包含来源节点 ID、关联边 ID、类型、文本或资源引用及可用状态；AI、生成节点分别适配模型能力。
- 不改变外部接口、持久化格式或旧文档结构。

## 三、依据分析结论实施的专项改动

**这一部分回答“按照结论，具体怎么做”。六项都必须落实到代码或明确的状态保护行为，并纳入验收，不能仅写一句“采纳／不采纳”就算完成。**

### 1. 保留自研引擎 → 完成现有引擎的局部优化

**并入 P1 手势更新、P2 视口与渲染隔离。**

- 在事件与状态写入之间接入帧调度，多选拖动改为批量更新。
- 分离高频视口状态和低频文档提交，拆分交互上下文，减少无关正文订阅。
- 缓存世界坐标连线路径；平移不重算几何，节点移动只更新受影响路径。
- 保留内容抬升、层叠、选中、复制拖动、撤销及旧文档行为。

**验收：**纯平移且可见集合不变时，静态正文不重新渲染；拖动与缩放正确，菜单和命中不偏移。保留引擎不等于保持当前实现不动。

### 2. 不采用全局挂载策略 → 完善按节点虚拟化与状态保护

**并入 P2 生命周期。**

- 普通离屏内容继续裁剪；选中、正在交互、输出或生成中的节点，以及活动浏览器按节点保留挂载。
- 可见节点集合不变时，不反复触发内容挂载更新。
- 预加载边距按屏幕距离换算，避免不同缩放倍率下行为差异过大。
- 检查编辑器、媒体和浏览器离屏返回状态，修复本轮改动引入的状态丢失。
- 提供浏览器会话资源实机记录步骤，由用户根据机器余量逐档检查；自动脚本只检查保活规则。本轮不增加后台自动卸载，不以销毁活动网页换取更低内存数字。

**验收：**一个节点输出不会导致全图挂载；活动节点不被错误卸载；浏览器表单和导航状态不因画布离屏而被清空。

### 3. 局部采用 transform → 真正接入普通展示内容

**并入 P2 局部缩放。**

- 图片、社媒、表格/数据、演示、文档及非 YouTube 视频的普通展示正文采用局部 transform。
- 文本和思维导图编辑器、AI/生成输入区、浏览器及 YouTube 嵌入保留原有专用路径。
- 保留内容抬升，不建立包住全部内容的共同缩放父层。
- 同步处理内容尺寸、滚动区域、编辑态切换、菜单定位和点击坐标。

**验收：**低、中、高倍率下排版、滚动和命中一致；编辑器输入和浏览器交互不回归。不能只增加一个缩放样式就标记完成。

### 4. 保留 IPC → 优化收到数据之后的显示与订阅

**并入 P1 AI 显示合批。**

- 保持网络读取和协议解析及时执行，不用显示节流阻塞传输。
- 将小片段合并为显示帧更新，后台用定时机制兜底。
- 完成、停止、异常及会话退出时按现有规则处理剩余缓冲。
- 正文只订阅当前会话；运行节点标识与正文变化分开，避免每个片段重新计算全图挂载例外。

**验收：**高频小片段下减少显示更新，首字与尾字正常；并发、后台、停止及异常场景不丢内容；现有传输隔离与清理行为保持不变。

### 5. 不整体迁移进程 → 消除重复编码并保证保存正确性

**并入 P1 会话增量保存。**

- 对已确认使用不可变更新的 AI 会话，在编码前判断是否变化。
- 将“计算过编码”与“成功保存”分开，失败不能被缓存误判为已保存。
- 处理删除重建、缓存失效、切换及写入期间出现新更新的情况。
- 单独记录图文档全量编码和历史深拷贝成本；本轮不改成补丁日志，不调整数据所有权。

**验收：**未变化会话不重复编码；失败可重试；保存期间的新内容不丢；刷新恢复结果一致。只减少编码次数、不保证恢复正确，不算完成。

### 6. 不引入复杂动效与新材质 → 实施短导航和世界网点

**并入 P3 背景与导航。**

- 网点拆为独立呈现层，保留 24 世界单位的基本间距和现有主题色。
- 平移改变网点偏移，缩放改变间距；低倍率逐级稀疏化。
- 定位节点和适应画布使用约 220ms 的短缓动；连续导航以最后目标为准。
- 鼠标、滚轮、键盘等用户输入立即中断导航，从当前视口继续操作。
- 减少动态效果模式直接定位；不增加完整弹簧、双段推近、玻璃模糊或噪声材质。

**验收：**网点与世界坐标一致，负坐标不跳动；导航落位准确、能够打断，不出现延迟拉回。

## 四、回归、交付与完成标准

### 执行顺序

1. 固定当前工作区、改动前源码与已有结果，保留原有未提交改动。
2. 按第二部分阶段推进，同时落实第三部分对应专项，不重复建立另一套任务。
3. 先补齐实现，再运行针对性回归；修复后只复测受影响范围。
4. 完成不打开窗口的综合检查；需要打开窗口的验证全部交由用户，不再自动运行窗口夹具。
5. 同步计划与执行记录，交付完整实机测试表。

### 自动验收：仅限不打开窗口的检查

- 功能覆盖手势、撤销/取消、导航、AI 流式、上游输入、来源定位、保存恢复、自动保存、退出清理和旧文档兼容。
- 最新代码必须通过类型检查、静态检查、Web 构建及桌面构建。
- 自动脚本可检查批量写入、订阅隔离、保活判定、末帧提交和数据一致性；这些结果不等于真实帧率、输入延迟或显示清晰度。
- 保留无窗口的编码/历史复制诊断，并明确其内存存储替身不包含磁盘、IPC 或完整保存延迟。
- 已有窗口夹具结果只归档，完整与不完整记录均不升级为实机验收证据；不继续跑齐窗口样本，也不据此重新选型。
- 不重跑已经结束的框架、传输、进程和动效选型。发现正确性错误或稳定退化，修复具体实现，不通过降低功能或删除测试获得通过结果。

### 用户实机测试交付

沿用现有 33 项检查表，补齐生成节点文本预览与来源定位步骤。最终回复直接输出表格，而不只是给文件路径。

用户在实际产品中检查 30／100／300 节点的拖动、平移、缩放、输出及混合操作。浏览器从 1 个、10 个逐步增加，机器余量允许才尝试更多或 50 个；系统可用内存低于 2 GiB 或已经卡顿时停止增开。量化比较必须先保证版本、画布和环境可比；不强制用户复现自动夹具，不预设实际优化幅度。

| 编号 | 对应阶段／专项 | 前置条件 | 操作步骤 | 预期结果 | 用户结果 |
|---|---|---|---|---|---|
| 固定编号 | 同时对应第二、三部分 | 节点、数据和环境要求 | 用户可以照做的步骤 | 可判断通过或失败的表现 | 默认“待测” |

覆盖手势、复制拖动、撤销、并发输出、保存恢复、输入法、菜单层级、浏览器操作、离屏状态、输入来源、旧文档、网点、导航打断及减少动态效果。需要真实网络或额度的项目单独标识，由用户执行。

### 完成标准

- **第二部分的阶段任务与第三部分的六项专项全部落实，不能以“结论已经写好”代替实施完成。**
- 最新代码完成自动回归和构建，结果与代码版本对应。
- 脚本结论与实机结论分列；模拟诊断不冒充性能验收，实际体验未由用户检查前保持“待测”。
- 原计划、执行记录和实际代码一致。
- 完整实机测试表已经交付，未由用户执行的项目保持“待测”。

**本轮开发交付完成，不等于用户实机验收已经通过。**用户实机检查属于后续验收，不由自动脚本结果代替。
