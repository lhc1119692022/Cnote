# 808 Wan 视频接入

本规则仅针对 808 渠道：video-808relay，或明确指向 808 的旧 video-api 渠道。Kacang 和其他供应商的参数、传输选择及 HTTPS 校验不变。

- 使用模型列表实际返回的 ID，按 Wan 3 家族识别参数规则，不改写模型 ID；包括 wan-3、wan-3.0、wan-3.0-1080p 及家族变体。
- 优先发送 duration，时长为 1–30 整数秒。不重复发送兼容别名。
- 分辨率不以固定白名单阻止请求；不强制降低清晰度。六种画幅为 21:9、16:9、4:3、1:1、3:4、9:16；auto 按 16:9 提交。
- 多模态最多 10 张图、5 个视频、5 个音频，允许纯音频参考；发送 image_urls、video_urls、audio_urls。
- 首尾帧采用 input_reference 和 image_end，首帧必需，尾帧可选；最多两张。
- 视频本地素材统一上传到自定义媒体存储，使用返回的公网地址；旧内联选择迁移到自定义存储，不再向视频接口发送 Data URL。未配置存储时在准备阶段报错。
- 808 接受 HTTP/HTTPS 媒体地址，不套用 Kacang 的素材域名限制；上传服务本身的 HTTPS 安全要求保留。
- 808 渠道的明确传输选择优先于旧适配器副本，并在规范化时同步；Wan 家族能力按用户确认覆盖旧缓存。
- 音频开关暂保留原实现 generate_audio，不新增字段猜测；服务端是否采用此字段尚未证实，不以模拟测试声称其有效。
- 失败时保留任务 ID、错误码、返回状态和有限诊断字段；不保存完整响应中的素材和密钥。

依据：2026-09-18 用户确认、新视频调用脚本和官方 llms.txt 交叉核对。官方列表包含 wan-3.0 / wan-3.0-1080p，但为其提供聊天接口示例，未解释异步视频接口参数或音频开关。因此保留当前异步视频调用流程，不自动改接口或重复提交付费任务。模拟测试仅验证本地请求行为。
