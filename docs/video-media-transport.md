# 视频素材传输

配置校验先于素材准备，素材准备先于模型提交；任何准备失败都不创建视频任务，也不自动切换传输方式。

## 已有地址不是传输设置

已有公网素材在提交前进行匿名 HEAD 检查；自定义 Worker 同源素材先通过 /prepare 确认保留期，临近到期时返回新的副本 URL。外部地址的保留期无法确认时，在请求汇总中标记未知，不声称模型服务一定可读。

## 本地素材统一使用自定义媒体存储

视频参考图片、视频、音频先向用户配置的存储服务上传，再将返回的公网地址提交给模型。内联提交选项与执行分支已移除；历史 Data URL 输入仍可以读取为本地文件，但不会直接进入视频请求体。

- 配置来自“本地存储”：服务地址、上传路径、表单字段、响应路径和独立令牌。
- 底层按 multipart 表单上传，上传凭证与模型凭证保持独立。
- 历史内联选择迁移到自定义存储；没有配置存储时，本地素材在 preparation 阶段阻断，不提交生成任务。
- 已有公网素材、纯文生视频与已提交任务的恢复轮询不需要重新上传。
- 历史渠道的自定义上传地址仅在全局存储未配置时使用；已废弃的供应商上传路径不会恢复执行。
- 图片生成协议自身的文件编码与生成结果解码不在本次视频传输清理范围内。

## 内容去重与刷新

按文件实际内容计算 SHA-256，不以文件名或大小判定相同文件。客户端在本地持久保存上传地址，按存储配置、凭证与 MIME 类型隔离缓存。跨任务或并发请求复用前匿名检查地址；404/410 或签名过期会重新上传，暂时性读取失败不会自动创建重复对象。

随附 Worker 按内容哈希存储，已存在的对象直接返回原地址，不重复写入或修改原文件名。此服务端优化需要重新部署媒体 Worker。不会自动删除历史对象，避免破坏仍在运行的任务或旧画布引用。

进入存储页自动查询对象和占用；取消固定轮询。重新聚焦或恢复可见时，仅在距上次更新满 5 分钟后刷新。上传、删除后立即更新，隐藏期间发生的变动在恢复可见时补刷新。后台更新不覆盖正在编辑的配置；刷新失败会保留旧数据并显示提示，重复聚焦的失败重试也按 5 分钟节流。手动刷新仍可随时使用。

## 生成前检查与错误

提交前显示实际准备好的图片、视频、音频 URL 数量（首尾帧计入图片）。没有对应请求字段时阻断，不静默丢弃素材。客户端检查不等于模型服务可读；创建接口拒绝仍显示素材摘要及脱敏后的 HTTP 状态、错误码、请求 ID。远端已有链接 404/410 时仅在本地副本存在时补传，权限和网络失败不重复上传。

用户当前 Worker 的独立升级版及部署说明见 workers/custom-media/README.md。原始脚本和既有远端对象均保留。

## Kacang 与 HTTP 206

Kacang / Doubao 拉取参考素材时只接受匿名可读的完整 HTTP 200 文件。R2 公共开发域名（`*.r2.dev`）、R2 S3 兼容地址和部分 CDN 在收到 `Range` 时会返回 HTTP 206 Partial Content，上游就会报 `Failed to fetch reference image: HTTP 206`。

自定义媒体存储必须同时满足：

- Cnote 里填写的服务地址是媒体 Worker 的公网源站，例如 `https://cnote-media.your-name.workers.dev`。
- Worker 的 `MEDIA_PUBLIC_BASE_URL` 也指向这个 Worker 源站，不要填 `pub-*.r2.dev` 或存储桶直链。
- `GET /media/{key}` 无需登录即可下载完整文件；对 `Range` 请求仍返回 200，而不是 206。

上传成功只说明 Worker 收下了文件。若返回的读取地址仍是对象存储直链，Kacang 还是会失败。改好 Worker 后需要重新上传参考素材，已保存的 `r2.dev` 地址不会自动修复。

创建任务时如果桌面网络层被中止，通常是上游在拉取参考图时卡住或超时，先按上面检查素材地址，而不是反复重试同一条直链。

## 验证边界

“验证上传”仅在自定义媒体存储配置齐备时提供。测试文件按内容复用，首次或原文件被删除后才重新上传；不提交生成任务。存储连通性检查不代表供应商接受最终视频请求。

`test:generation-inputs` 和 `test:media-policy` 覆盖生产请求构造、旧配置迁移、已移除的供应商上传不可执行、HTTPS 直接引用、历史内联配置迁移、自定义存储及失败阻断。所有网络均为 mock；不代表用户存储已经通过真实端到端验证。
