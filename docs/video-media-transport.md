# 视频素材传输

配置校验先于素材准备，素材准备先于模型提交；任何准备失败都不创建视频任务，也不自动切换传输方式。

## 已有地址不是传输设置

画布连线或添加的 HTTPS 素材直接进入请求体，不重新下载、转成 Data URL 或上传。因此设置中不再提供“已有 HTTPS 地址”。供应商能否读取该地址仍取决于其访问权限与地址有效期。

HTTPS URL 是远端文件的地址；Data URL 则把文件内容编码在字符串中。两者可以同时出现在同一个视频请求里，但 HTTPS 不属于 Data URL 的一部分。

## 本地素材必须显式选择

新增或保存支持视频的渠道时，必须选择本地素材传输方式。没有默认选项，也没有“自动”规则。

| 传输方式 | 实际行为 | 配置来源 |
| --- | --- | --- |
| 内联 Data URL | 本地素材编码后直接放入视频请求体 | 不用存储服务；仅适用于渠道明确接受 Data URL 的视频接口 |
| 自定义媒体存储 | 向自己的服务发送 multipart POST，取回 HTTPS 读取地址 | “本地存储”中的服务地址、上传路径、表单字段、响应路径和独立令牌 |

上传方式只保留自定义媒体存储。供应商预签名和供应商 multipart 上传的选项、协议/路径控件及执行分支已移除，需要时再按具体渠道文档添加。

自定义存储底层仍按原接口契约使用 multipart 表单上传，这是存储适配的实现细节，不再作为独立的传输选项。内联 Data URL 不受此次精简影响。

历史渠道中显式保存的自定义上传 URL、字段及独立凭证继续保留；全局自定义媒体存储未配置时才使用这些旧配置。已配置全局存储时优先使用全局设置。上传始终使用存储凭证，不使用生成渠道的供应商凭证。

## 历史配置与失败处理

- 旧 `auto`、`public-url`、`presign`、`multipart` 和缺失值在读取时视为尚未选择；历史供应商路径不会被执行，也不会根据已有路径或全局存储自动改用另一种方式。
- 使用本地素材前必须重新选择；纯文本或全为 HTTPS 素材的现有请求无需上传，可继续执行。重新编辑并保存视频渠道时仍须明确选择。
- 显式的内联、自定义存储配置保持不变；已提交任务的快照和恢复轮询不受影响。
- 内联限制按编码后的 JSON UTF-8 总大小检查，包含 Base64 膨胀与提示词。准备错误标为 preparation 阶段，与 creation 区分。

## 验证边界

“验证上传”仅在上传方式已明确且配置齐备时提供，不用于内联或已有 HTTPS 素材。它会真实上传一个测试文件，但不提交生成任务；上传成功不等于供应商接受最终视频请求。

`test:generation-inputs` 和 `test:media-policy` 覆盖生产请求构造、旧配置迁移、已移除的供应商上传不可执行、HTTPS 直接引用、Data URL、自定义存储及失败阻断。所有网络均为 mock；不代表用户存储已经通过真实端到端验证。
