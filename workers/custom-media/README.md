# Cnote 自定义媒体 Worker 升级

本目录的 worker.js 基于用户提供的 D:/Downloads/worker.js，不是仓库中另一套上传服务的替代配置。

## 部署

1. 先备份当前线上 Worker 脚本。
2. 将本目录 worker.js 的完整内容替换到原 Worker 并部署。
3. 保留原 R2 绑定 MEDIA_BUCKET、原密钥 CN_MEDIA_TOKEN、原 Worker 域名，不需要新建桶或迁移文件。
4. R2 生命周期仍由控制台配置：media/ 前缀、上传满 14 天删除。脚本不会创建、修改或关闭此规则。
5. 保持 14 天规则与脚本 RETENTION_MS 一致；如果改为更短期限，必须同步脚本。Worker 无法读取控制台规则，expiresAt 是根据对象 uploaded 时间和该配置计算的保守截止时间，不是云端删除承诺。

## 行为

- 老随机文件名 URL 保持可读；不会批量改名、删除或迁移旧文件。
- 新上传采用 media/日期/内容哈希-MIME哈希。同一天相同内容不会重复写入，并使用条件写入防止并发覆盖；不同日期的无缓存请求可能产生新副本，这是让新请求获得新生命周期的有意取舍。
- POST /prepare 使用现有 Bearer 凭证，仅接受 media/ 下的对象键。剩余超过 48 小时直接返回；不足时读取文件并创建今天的副本。不会覆盖或删除旧对象。
- 续存后返回新 URL。已有任务使用的旧 URL 不会被改写，也不会因此延长；旧对象仍按原生命周期到期。
- 48 小时是提交时的安全缓冲，不保证无限排队、人工删除或规则改变后任务仍可读取。没有实现任务锁、租约或模型完成前禁止删除。
- GET/HEAD 匿名读取；HEAD 返回 X-Cnote-Expires-At 和来源标记；Range GET 仍返回完整 HTTP 200。禁用缓存，避免 R2 已删除但客户端缓存检查仍通过。
- 旧 Worker 不支持 /prepare，客户端会要求部署升级版，不会把未知保留期伪装成已验证。

## 验证边界

本地自动测试覆盖鉴权、哈希校验、同日并发去重、元数据、旧地址读取、临近到期续存、旧对象不被改动和 Range 200。客户端测试覆盖 HEAD 检查、404/410 补传条件、403/429/5xx 不自动补传、未知保留期提示、实际 URL 摘要及生成错误脱敏。

尚未部署线上，未使用真实账户令牌执行远端测试，未提交付费模型任务。升级后需要用专用测试文件完成线上上传、重复上传、读取和删除后补传验收；不能把本地模拟测试当作线上成功证明。
